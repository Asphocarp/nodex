# Frontend

## Stack
- React 19 + TypeScript (`strict`)
- Tailwind CSS + local UI primitives in `src/renderer/components/ui/`
- BlockNote editor for Page bodies, bound directly to a Page-owned Y.Doc on primary surfaces
- Atlassian Pragmatic Drag and Drop for board drag-and-drop

## Structure
- App shell: `src/renderer/app.tsx`
- Domain components: `src/renderer/components/kanban/`
- Active local conversation renderer: `src/renderer/features/local-conversation/`
- Worktree initialization activities use the single `WorktreeInitActivityList` owner for both the pending-worktree route and completed transcript items. A recovery-action footer targets only the final activity; row keys include whether the row is that target so a new phase remounts the old target closed and the new target open. Completed transcript activities have no action target and start collapsed, while a running conversation is a non-disclosure shimmer row. All worktree/setup output must flow through the shared embedded/plain `ThreadCommandShellBlock`; do not add a pending-only `<pre>` or independent expansion state.
- Terminal command output uses the safe `TerminalAnsiText` token renderer. Preserve the reference normalization order (destructive backspaces, then carriage overwrite), whitespace, semicolon SGR state, color-class CSS, and final-active-decoration behavior. Render React text spans rather than HTML. The shipped parity contract intentionally has no effective CSS for bright backgrounds, palette colors, or truecolor even though their parser tokens are recognized.
- Editor subsystem: `src/renderer/components/kanban/editor/`
- Owned Document surfaces: `src/renderer/components/block-documents/` with lifecycle/descriptor helpers in `src/renderer/lib/`
- Shared hooks/helpers: `src/renderer/lib/`
- NFM conversion/parsing: `src/renderer/lib/nfm/`
- Storybook workspace: `packages/storybook/` with colocated `*.stories.tsx` under `src/renderer/`
- Workbench shell: `src/renderer/components/workbench/workbench-shell.tsx` renders the content/execution sidebar in the order optional `Pinned`, `Library`, `Projects`, and `Chats`, a session thread page, Project-independent Library routes, plus independent right and bottom panels for session-attached tabs.
- Workbench sidebar organizer state: `Pinned`, `Library`, `Projects`, and `Chats` header collapse state belongs to `sidebar.collapsibleSections` in the sidebar prefs owner, not to the sidebar content subtree. The real and floating sidebars can mount/unmount independently during explicit toggle and auto-reveal motion, so header disclosure state must flow through the same WorkbenchShell sidebar prefs prop/setter path that persists width, collapsed state, and section settings. Pinned composition is fixed projection state, not a layout preference.
- Library navigation: `ProjectSessionSidebar` mounts `SidebarLibrarySection`; the legacy generic left-sidebar component is not the production owner. The section is a bounded lazy ownership projection with one composite `role="tree"`, roving focus, directional/Home/End/typeahead behavior, and active-path force inclusion. It shows top-level and Page-owned Page/Database Blocks; a multi-View Database may disclose its hosted Views. It never renders Data Sources or Database row Pages as tree children. `More` and the header book action open the full searchable Library workspace.
- Library mutations: New creates an Untitled Page or single-Source Database without a naming modal and opens it; an Untitled Page focuses its collaborative title. Context actions and the shared sidebar DnD builder use the same revisioned Library operations for ownership moves. Dropping or granting onto a Project always presents recursive `Read` versus `Read & write` confirmation, and navigation itself never creates a grant or changes a Database binding.
- Workbench app shell: top chrome controls must declare through the workbench `HeaderAction` registry so `WorkbenchShell` owns final ordering, `gap-1.5` spacing, measurement, and cross-panel reservation even when declarations come from separate components. Keep the bottom-panel toggle and side-panel toggle in the fixed global header, ordered bottom first and side second, with shared bottom-panel SVGs and an animated `header-shell-slot` width that follows the regular right-panel spring. Keep the active thread title in the fixed global header center surface through `ThreadHeaderPortalProvider`, and keep the thread summary toggle registered as the center `HeaderAction` `local-thread-summary-panel-toggle`, rendered by the center inline rail in that same surface so it sits at the thread/right-panel boundary without creating an in-flow toolbar row. Keep right-panel tab creation plus expand/restore in the right-panel toolbar-height tab header, keep bottom-panel tab creation plus the plain `Close` X action in the bottom tab header, and implement right full-width mode by collapsing only the main thread viewport while the bottom panel remains visible. Keep the right-panel aside on `z-[41]` and the fixed global header above it so persistent bottom/side-panel toggles remain clickable in regular and full-width right-panel modes. The fixed-width right-panel content canvas must anchor to the aside's right edge while the overflow-clipping aside animates or resizes; shrinking or closing the regular panel reveals/clips content from the left so expand/restore and Card Stage's trailing toolbar actions remain fixed to the viewport edge instead of following the sash off-screen. Its target `width` is the sole reactive horizontal dimension; keep `min-width` statically at zero so an earlier target cannot survive as a second layout constraint after the sash shrinks. Panel tab headers must not be `draggable`; the fixed global header is the only native drag region for this top row. The fixed visible `header-shell-slot` rectangles and the right-panel tab header's start/end reservation wrappers still must be `no-drag` even when they stay `pointer-events-none`; these rectangles overlap clickable titlebar controls and must be excluded from Electron's native drag region. The right-panel expand/restore button and its trailing `right-panel-tab-bar-header-spacer` live in the tab header's after-list flow and use the measured right header width, not an absolute overlay. Thread pages use `data-app-shell-header-edge-scroll` on the fixed global header: it is true only for `thread-edge-scroll`, an effective main width of at least `96rem`, and no full-width right panel. The physical main frame border is transparent only in the actual wide edge-scroll state without a right panel; do not add a separate absolute header-divider node such as `data-app-shell-main-content-header-divider`.

- Panel tab context menus: feature-provided items come first, followed by a separator and generic `Close`, `Close other tabs`, and `Close tabs to the right` actions. - Panel tab sizing and rapid close: a tab strip distributes all tabs equally from a zero flex basis within shared `90px` minimum and `160px` maximum widths; title length never gives one tab a larger share. The strip width clamps between the aggregate minimum and maximum, fills the unobscured row width between those bounds, and subtracts the measured in-row trailing-action width before distribution. Tab enter/exit geometry animates for 150ms while the strip retains the larger pre-exit tab count until all exits finish. Direct close-button and middle-click mousedown capture the target tab's `offsetWidth` and temporarily lock the whole row to that one width, preserving the next close target until the pointer leaves the tab row. Keep this state local to `AppShellTabs`; do not persist it, do not use it for context-menu bulk closes, and exit it before/when panel tab drag starts, tab-row wheel scrolling occurs, or a context menu opens. Rapid close must not influence which tab becomes active after close: `WorkbenchShell` routes close-button, middle-click, keyboard, and menu single-tab closes through same-leaf MRU, with right-neighbor then left-neighbor fallback only when MRU cannot answer. Temporary sizing must not change `data-panel-tab-id`, `no-drag` ownership, Pragmatic Drag and Drop source data, or the non-layout-shifting insertion marker contract.

- Workbench pinned projection is fixed and lane-aware, not preference-driven. A project-scoped pinned chat renders first inside its own project folder; that folder's regular lane follows immediately with no extra heading or card chrome. Projectless pinned chats render as standalone rows in the global `Pinned` section, followed by pinned project folders; pinned rows whose project is temporarily unknown also fall back there. Unpinned project folders render under `Projects`, and projectless non-pinned chats render under `Chats`. Hide the entire `Pinned` section header when there are neither projectless/fallback pinned chats nor pinned project folders. Manual order applies only within each regular lane: start from stable recency order, then replace the slots belonging to stored durable thread IDs; new, temporary, and otherwise untracked rows retain their recency slots until a later manual drag reconciles them. A project manual reorder applies only its returned sidebar snapshot; it must not merge/refetch project-session summaries or emit a project-session change. Project-local pinned rows use their separate pin lane, and pin/unpin must not erase a thread's project manual identity. Project-folder thread drop zones keep the physical `project:<id>` dnd registration stable for the full gesture; that registration owns pinned-lane preservation and resolves it only at policy/drop dispatch, rather than exposing a caller-selected mode or encoding the lane into droppable ids. The global `Pinned` target is likewise one shared droppable registration enabled by the active payload; never register the same `sidebar-thread-container:pinned` id once for project drag and again for task drag inside the shared context. Thread insertion intent refreshes from both dnd-kit `onDragMove` and `onDragOver`, so moving across a row midpoint without changing the hovered row updates the indicator before drop. Persistence failure clears the optimistic projection and flows through the sidebar's visible error reporter.
- Workbench shell geometry is continuous visual state. The shared element-size observer owns stable callback refs, reads `borderBoxSize` with a `contentRect` fallback, and writes raw width/height to MotionValues; panel sizes and animation targets derive from those values and bind directly to motion elements. React state may project only guarded semantic changes such as shell-width classes, summary layout modes, and edge-scroll booleans. Never mirror each ResizeObserver or pointer-resize sample into `WorkbenchShell` state, and never put a function returned by `useEffectEvent` in a dependency array.
- Keep renderer interaction state at the intent boundary. A currently valid menu highlight, filtered selection, or visible projection that can be computed from props plus intent must be derived during render, not repaired by an Effect that calls `setState`; a no-op functional updater can still join a nested passive-update cycle while another transition is pending. Async pending-key sets are operation-owned: acquire atomically before the request, refresh authoritative data inside the request, and release in `finally`. Do not prune transient state by watching freshly projected collections in an Effect. Hooks whose mutation functions are consumed by dependency arrays or passed into drag-and-drop trees must return stable callbacks.

## State and Data Access
- API boundary: always go through `src/renderer/lib/api.ts`.
- Low-frequency server state uses TanStack Query under `NodexQueryProvider`. Add keys in `src/renderer/lib/query-keys.ts` and query option helpers in `src/renderer/lib/query-options.ts`; feature hooks should compose those helpers instead of inventing component-local ad hoc query keys.
- Query client defaults are part of the renderer contract: `staleTime: 30_000`, `gcTime: 5 * 60_000`, query `retry: 1`, no focus/reconnect refetch, and mutation `retry: false`. Query Devtools are development-only and must stay hidden in Storybook.
- Query functions and mutation functions must still call the `lib/api.ts` transport facade. Do not call Electron bridges, browser fetch routes, or main-process channels directly from query code.
- Mutations should update the narrow cache when the server returns the complete next value, otherwise invalidate the exact affected key. Examples: project reorder writes `projects.list`; project create/update/delete invalidates `projects.list`; a forward Document-version restore resynchronizes the affected Document and refreshes its Card timeline; local-environment saves update the snapshot and invalidate that project's config list.
- Project-session hot paths use summary/detail cache split. Sidebar rows and cold-start project/projectless scopes use `projectSessionSummariesQueryOptions(projectId)` / `project-sessions:list-summaries`; selected sessions, hover/focus prefetch, and explicit panel/tab operations use `projectSessionDetailQueryOptions(sessionId)` / `project-sessions:get` with the default 30s stale window. Session switching must not call `project-sessions:list`; keep full `project-sessions:list` for rare slow paths that need every session's tabs/layouts. Warm recent-session UI state is retained by a Workbench-owned React Activity MRU with a cap of four sessions total: the active full-detail session plus the three most recent inactive warm full-detail sessions. Activity owns cross-session warm trees; DB View scroll uses renderer-local pre-paint scroll snapshots; Card Stage tab-to-tab switching uses AppShellTabs layout-retained panels with scroll snapshots only as reveal/remount fallback. Do not turn all `db_view` tabs into globally keep-mounted tabs to solve switching.
- The Activity MRU is an ordered list of stable session IDs. Array order is the recency signal; do not add timestamps or fresh metadata objects that make an unchanged retention set look different to React. Recompute from the latest ref-backed list and dispatch only when the ordered identities change.
- Codex sidebar state uses `queryKeys.codexSidebar.snapshot()` and `queryKeys.codexSidebar.pinnedThreads()`. The snapshot query must first request `codex:sidebar:snapshot({ refresh:false })` and remain a low-frequency SQLite read model cache; it is not the external-thread discovery mechanism. `useSidebarThreadSyncModel` must not force a full app-server `thread/list` during mount or thread-open. It may schedule a low-priority `policy:"stale"` mount reconciliation, uses `policy:"stale"` on window focus/visibility regain, uses a focused visible 60s heartbeat, and debounces app-server host messages (`threadSummary`, title/delete, thread-start progress, and reconnect). Project/source changes use `policy:"force"` because cwd-to-project assignment may change. `project-sessions-changed` events are session container/link events only: they must not call `codex:sidebar:sync`; they should mark affected scopes for lightweight `project-sessions:list-summaries` refresh. Main-process `sidebarSyncUpdated` host messages are applied directly to the sidebar snapshot query and must not be routed back into another stale sync loop. Sync results that report `changedProjectIds` or `projectlessChanged` must refresh the matching project/session summaries even when those projects are inactive; full project-session detail should be loaded only for selected sessions or explicit panel/tab actions. If a sync result arrives before the session refresh callback is ready, queue the affected scopes and drain them when the callback is installed. Pinned-thread reads intentionally use query freshness and explicit mutation returns rather than a thread-open-side reconciliation.
- Do not put a whole query or mutation result object in React dependency arrays. Destructure stable fields/functions such as `data`, `error`, `isPending`, `mutateAsync`, or `refetch`, and depend on those values.
- High-frequency external events may enter React state only at semantic transitions. Keep pointer/geometry samples in refs or MotionValues, and use `useDistinctState` for direct primitive transitions that must render. A functional state updater returning its current value is not an equivalent guard: React has already enqueued that update, so it can still participate in a pending commit/effect cycle.
- Keep Query out of high-frequency or optimistic ownership domains: `kanban-store`, local-conversation streaming manager state, terminal lifecycle, browser/webview manager state, drafts/forms, and localStorage-only preferences.
- Board state: `useKanban` uses a shared `kanban-store` optimistic journal (`baseBoard + pending/local overlays`) with LWW conflict superseding, rollback-on-failure, and store-derived cross-view sync. The store owns `BoardSummary`, not full `Board`; `cardIndex` entries must not contain full `description`. Board refresh is project/event/mutation-owned, not session-id-owned: first subscription and DB View warmup call `ensureFreshBoard({ maxAgeMs: 30_000 })`, while manual refresh, ambiguous realtime events, and mutation recovery can force a fetch.
- Hidden Activity-retained sessions are not active shell participants. Only the visible active session may write global panel measurements, register header actions, expose visible Browser webview ids, own composer overlay targets, or report thread view-active state. Scope `ThreadHeaderPortalProvider` to the active session's primary `SessionThreadPage`; never provide the global thread-header target around the whole workbench or panel trees, because nested conversation stages such as background-agent details must not become additional global-header owners. A full-width right-panel thread viewport passes inactive state to the thread stage unless runtime/request status still requires live controls.
- Page bodies: production Page Stage first prepares the exact `(projectId, pageBlockId)` owned-Document descriptor. `ydoc_primary` Pages load title/body only through their independent `BlockDocumentSurface`; Page description projections are not editor inputs or write callbacks and no runtime snapshot-editor branch exists. In NFM, child `page` and non-owning `pageRef` Blocks share one native-toggle-like outliner row. Resolve them through the membership-independent Page target read model, never through a Database-row summary: a child Page may have no Database membership. Idle collapsed rows render the exact-head rich-title summary without a provider. Clicking or Arrow-entering the title creates per-mount engagement and activates one target surface without changing disclosure; its collaborative Y.Text title replaces the projection, while its nested body `NfmEditor` is constructed only when disclosed. Expanded visible rows use that same target surface and place only its body editor at normal child indentation. Persist disclosure through the shared browser-profile toggle store keyed by the shell Block ID: an owning child uses its Page Block ID, while each `pageRef` uses its own occurrence ID rather than `targetBlockId`. Keep stable disclosure separate from per-mount title engagement, visibility, and provider activation, and derive effective expansion from current eligibility without overwriting preference during loading/error/cycle states. Editing engagement has priority over visibility-only admission but never exceeds the shared provider cap. The full-width row reuses BlockNote's toggle wrapper/button contract: 32-pixel header, 16/24 title typography, native 200-millisecond caret rotation, and one 24-pixel child indentation. Keep the frame, disclosure wrapper, and caret DOM identities stable across projected/loading/active/error slots; asynchronous target runtimes replace title/body slots only. The expanded transform must target only the disclosure wrapper's direct caret so an expanded ancestor cannot rotate a collapsed nested Page. Route `Cmd/Ctrl+Enter` from either a selected Page shell or its live title header into that same occurrence-local disclosure owner; ignore events whose nearest Page body belongs to the current wrapper so a parent cannot collapse in response to a nested editor command. Scope embedded-surface handles by concrete editor and shell identity. Resolve ArrowUp/ArrowDown neighbors from the visible depth-first Block tree, use `EditorView.endOfTextblock` for host/body boundaries, and use the rich-title DOM geometry Adapter for the standalone title; ordinary wrapped-line movement remains native. A nested body editor must neutralize the host editor's extra top-level group margin, minimum empty-editor height, and trailing insertion gutter without changing deeper Block indentation. Its content root, container, and floating UI belong to one BlockNote interaction scope: document-level hover/drop routing resolves the deepest composed-path owner first and uses geometry only for unowned gutters, so a parent editor cannot claim a nested side menu. Never render storage/provider boundaries as nested cards, duplicate headers, or vertical editor boxes. Database property chips belong to an explicit Database View row composition, not the generic Page target. Toggle-list and inline Database rows follow the same summary-first/independent-target rule; foreign bodies never enter the host editor tree. Board/list/calendar/Page picker/command-palette default paths stay summary-only.
- Card Stage's local metadata form synchronizes from a versioned external snapshot: Card ID, metadata revision, Database membership identity, and compatibility capability determine whether the source changed. Fresh projection objects and command callback identities are not data changes and must never retrigger form/schedule state application. Mutation callbacks used by synchronization effects belong behind an Effect Event so command identity stays outside the snapshot dependency model.
- Cross-surface Page/Block DnD: carry only Project/store/source parent, stable root IDs, and disposable labels. Use `copyMove`; resolve default Move versus Option/Alt Copy from the current dragover/drop event, and drive drop effect, BlockNote-aligned indicator, label, and submitted `BlockTransfer.mode` from that one helper. Do not serialize NFM/Page bodies, insert `pageRef` as a hidden substitute for Move, show a second native caret, or remove the source optimistically. Same-Database Kanban reorder remains a View-position operation.
- Command palette root mode must be built from current session, panel, tab, and settings shell actions. Root mode searches command rows only; chat and card search live in explicit modes opened by their own shortcuts or by root-mode mode-switch rows, while the file-search shell remains a development-only placeholder until it has a real backend. Unsupported shell actions may appear only in development builds as disabled rows with a `Mock` badge, gated from the catalog with `import.meta.env.DEV`; production command catalogs must not include mock rows. Nodex-only shell actions such as DB View belong in the closest matching command group.

The exported `COMMAND_MENU_REFERENCE_ICON_MANIFEST` records extracted asset source paths and fallback status so icon coverage gaps are visible.
- Reference-only menu actions must follow the same rule as command-palette mocks: production models do not include them, while development and Storybook can opt in with explicit `showMockActions` / `showReferenceMocks` inputs and visible `Mock` badges. Keep real but context-disabled actions visible without a `Mock` badge, and gate runtime defaults with `import.meta.env.DEV` instead of a broad feature-flag framework.
- Page search: local Board-summary fields can be searched immediately in Pages mode. Full-content search must go through `pages:search`, which searches fresh Library Page Document projections, evaluates every result against the selected Project access contexts, and returns Page ids plus bounded excerpts; do not load every Project's full board to build a renderer description index. Fetch full bodies only through explicit detail hydration.

A primary Card title/body never enters `Reload Latest` / `Overwrite Mine`; Yjs merges those edits and only the temporary legacy content branch may show the old whole-Card recovery UX.

- Project lifecycle: `use-projects.ts`.

- Session tab bodies should stay reusable: DB view hosts, Page Stage, terminal, and Browser surfaces mount behind `ProjectSessionTab.kind`; do not rebuild separate shell-specific versions of those features. Durable Page Stage tabs should stay mounted in stable app-shell body wrappers while their leaf is mounted. Inactive retained Page Stages must be parked with layout-preserving visibility/inert semantics, not `hidden` or `display:none`, so their native scroll/editor state remains intact across tab switches; only the visible Page Stage may own shared close/persist/session-snapshot refs. Deactivation still flushes pending editor/scroll state, and scroll snapshots are fallback for remount/reveal only. Nested Page navigation belongs to the reusable Page Stage toolbar, but navigation history does not belong to tab persistence: tab config stores only the Page identity, access context, and title snapshot. Resolve the complete root-to-parent ownership path through one Project-scoped main-process read derived from current Page parents. Observe the target and returned ancestor identities for location/content changes, invalidate the Project path prefix when grants change, and never expose inaccessible ancestors. The current breadcrumb item reads the mounted Y.Text title publisher. Page Stage renders the result as a token-based `nav`/list breadcrumb with the current Page marked as the current page. Keep it single-line; deep trails expose hidden middle ancestors through the shared dropdown rather than wrapping or losing navigation.

Because the webview root is fixed under `document.body`, Browser tabs must resample placeholder `getBoundingClientRect()` from the owning right/bottom panel motion value as well as ResizeObserver/window events, so panel open/close transitions cannot leave the webview painted at a stale midpoint. Keep Browser chrome on the compact panel contract: a `h-toolbar-pane` toolbar row, shared square icon buttons, centered idle address input with skip-commit action targets, collapsed screenshot/comment actions on blank tabs, full-bleed responsive webview hosting, and the narrow `Local` blank-tab server list with storage-backed show/sort preferences.
- A retained inactive primary Card Stage keeps its Document provider subscribed for content catch-up but clears local Awareness so a hidden tab does not appear present. Deactivation/close uses the surface's bounded persist/checkpoint lifecycle; only the visible Card Stage owns shared close/persist/session-snapshot refs.
- Active conversation UI: keep Codex host-message ingestion in the singleton external store under `features/local-conversation/`, subscribe through per-thread selectors, then derive renderer-only projection data in `features/local-conversation/projection/*`. Keep transcript projection, composer-shell aggregation, search-unit derivation, turn-request stitching, and background-activity ordering upstream of JSX.

## Editor Patterns
- Keep custom editor behaviors in dedicated modules under `editor/`.
- Keep schema and extension composition centralized (`nfm-schema`, `toggle-list-schema`, extension helpers).
- `NfmEditor` must receive an explicit discriminated source. `legacy-snapshot` may use NFM `initialContent`, serialized-change debounce, blur flush, and external replacement. `collaborative-document` must use BlockNote's collaboration fragment/Awareness and must not install `initialContent`, serialize the whole body for persistence, or replace Blocks from a Card snapshot.
- Treat `BlockNoteEditor.prosemirrorView` as a mounted-view API. Tiptap returns a limited Proxy before mount and after unmount; reading `view.dom` from that Proxy throws even through optional chaining. Code that only needs the editor root must use BlockNote's lifecycle-safe `editor.domElement` and read it at interaction time instead of caching it during React render. Keep direct ProseMirror view access inside callbacks whose mounted-view ownership is explicit.
- Primary Card title and body share one surface-owned Y.Doc but keep local undo scopes. The rich-title contenteditable renders the validated Y.Text Delta through a DOM Adapter; React owns the surrounding toolbar/state but never reconciles the browser-mutated composition subtree. Intercept cancelable edits with a native `beforeinput` listener before the DOM changes—React's synthetic `onBeforeInput` is not an `InputEvent` boundary and cannot be cast into one. Non-cancelable/IME fallback reads both text and selection from live draft-DOM coordinates because committed segment offsets are stale after a browser mutation. Each writable mount has a distinct client/session origin; remote transactions do not enter its undo stack. The body UndoManager is registration/surface-owned and survives replaceable EditorView mount cycles; view cleanup removes only selection listeners, while extension/editor disposal destroys the manager.
- Start a managed Block drag only from the explicit BlockNote side menu after `blockDragStart` returns the authoritative root IDs. One window-local coordinator carries the source surface and logical parent to Document and Database targets. Same-surface reorder remains BlockNote-native; every cross-parent drop suppresses ProseMirror's cross-editor slice/text-caret path and submits one `BlockTransfer`. Nested targets arbitrate by the closest `.nfm-editor`, and Option/Alt is sampled again at drop.
- Add behavior regression tests next to editor helpers (`*.test.ts`).
- Preserve NFM round-trip compatibility when changing parser/serializer/adapters.
- For Card Stage rich-editor typing performance, follow `docs/card-stage-rich-editor-performance.md`.

## Component SOP
- Start from existing semantics, not from JSX. New UI behavior should usually begin in a projector, bucketizer, normalizer, or other renderer-facing adapter before touching leaf components.
- Keep leaf renderers dumb. Message/tool/request components should consume already-derived props such as lane membership, action eligibility, placeholder state, or copy text instead of recomputing those rules locally.
- Keep one canonical lane per semantic role. Final assistant content, leading user prefix actions, exploration groups, pending-request lanes, and diff lanes should each be derived once and rendered once.
- Keep transcript-special rows dedicated. Items such as context compaction, automatic approval review, and multi-agent activity should render through their own leaf components instead of falling back to generic system banners. Multi-agent headers include the shared subagent glyph, and row links resolve friendly names from receiver metadata or parent child memberships before falling back to raw thread ids.
- Keep poor-network reconnect in the transcript, not in shell resume state:
  - retryable transport/turn errors should materialize as `streamError` transcript items with expandable details
  - non-retryable turn failures should materialize as `systemError` transcript items
  - do not reuse `resumeState` placeholders or shell overlays for the `Reconnecting... 2/5` feature
- Prefer rendered behavior over source-looking class strings. If runtime behavior and an apparent source token disagree, treat the rendered CSS/output as authoritative.
- Keep component chrome subdued. Secondary actions should stay small, low-emphasis, and hover-revealed unless the product surface makes them primary. Hover reveal does not imply sequential keyboard focus.

## Frontend Testing
- Run targeted tests while iterating: `pnpm test src/renderer/...`
- Run isolated UI harness: `pnpm run dev:storybook`
- Treat Storybook as part of the UI contract. When adding or changing any user-visible UI, update or add the focused stories in the same change instead of leaving Storybook behind.
- Keep Storybook scenes canvas-first: use story variants, `args`, and `argTypes` for presets and controls instead of rendering custom preset/control sidebars inside story pages.
- Keep Storybook scenes production-backed: thread and card-stage stories should build state from the same projection/helpers used by shipped UI instead of hand-authoring parallel fake view models.
- Keep shared UI stories focused. Cover `dropdown`, `popover`, `tooltip`, `button`, `dialog`, and `settings` primitives with explicit regression states such as compact/icon-only triggers, long labels, search rows, flyout submenus, and compact-control tooltips instead of relying on a single catch-all gallery.
- Keep embedded kanban control stories focused on the actual regression surfaces: toggle-list rules/inline controls, card-ref floating toolbars, inline property strips, command-palette filters, and db-view toolbar rules should each have their own visible harness stories.
- Keep `settings/environments` stories flow-complete: workspace root, multi-config project rows, summary, edit, parse error, create-new, and environment-variable popover states should all be separately reproducible.
- Keep selector stories split by feature. Branch and environment selectors should not share one mixed story page; cover default, empty, busy/loading, long-label/path, and icon-sizing states independently.
- Keep menu-driven stories open by default through story-only harnesses. Context menus, sidebar menus, and project manager popovers should render their open state directly instead of asking the reviewer to right-click or click to reveal the actual surface.
- Current thread stories live under `src/renderer/features/local-conversation/view/` for composed stage scenarios and under `src/renderer/features/local-conversation/view/shared/` for focused transcript-special, tool, and request leaf stories. Keep transcript-special surfaces such as reasoning, todo lists, automatic approval review, and multi-agent activity in the transcript-special stories instead of forcing them into tool-call stories.
- Keep tool-call stories scoped to actual Codex tool families. Transcript-special surfaces that happen to originate from tool-like raw items still belong in transcript-special stories once the projector gives them their own semantic lane.
- Default renderer component tests to DOM-based coverage with Bun + `happy-dom` + `@testing-library/react`.
- Assert user-visible structure, labels, and behavior through rendered DOM queries; keep `data-testid` and raw class checks as fallback tools, not the default.
- Reserve HTML-string or server-render assertions for cases where serialized markup is the actual contract.
- Do not add source-string tests that only verify implementation text inside a file.
- Prioritize parser/editor and hook tests for regression safety.
