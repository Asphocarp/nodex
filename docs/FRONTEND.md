# Frontend

## Stack
- React 19 + TypeScript (`strict`)
- Jotai 2.20.2 plus the internal Maitai scope kernel for renderer-local App,
  Thread, Route, and Composer view state; see
  `docs/renderer-view-state-ownership.md`.
- Tailwind CSS + local UI primitives in `src/renderer/components/ui/`
- BlockNote editor for Page bodies, bound directly to a Page-owned Y.Doc on primary surfaces
- Atlassian Pragmatic Drag and Drop for board drag-and-drop

## Structure
- App shell: `src/renderer/app.tsx`
- Domain components: `src/renderer/components/kanban/`
- Active local conversation renderer: `src/renderer/features/local-conversation/`
- Worktree initialization activities use the single `WorktreeInitActivityList` owner for both the pending-worktree route and completed transcript items. A recovery-action footer targets only the final activity; row keys include whether the row is that target so a new phase remounts the old target closed and the new target open. Completed transcript activities have no action target and start collapsed, while a running conversation is a non-disclosure shimmer row. All worktree/setup output must flow through the shared embedded/plain `ThreadCommandShellBlock`; do not add a pending-only `<pre>` or independent expansion state.
- Terminal command output uses the safe `TerminalAnsiText` token renderer. Preserve the reference normalization order (destructive backspaces, then carriage overwrite), whitespace, semicolon SGR state, color-class CSS, and final-active-decoration behavior. Render React text spans rather than HTML. The shipped parity contract intentionally has no effective CSS for bright backgrounds, palette colors, or truecolor even though their parser tokens are recognized.
- Editor subsystem: `src/renderer/components/kanban/editor/`
- Owned Document surfaces: `src/renderer/components/block-documents/` with lifecycle/descriptor helpers in `src/renderer/lib/`
- Shared hooks/helpers: `src/renderer/lib/`
- NFM conversion/parsing: `src/renderer/lib/nfm/`
- Storybook workspace: `packages/storybook/` with colocated `*.stories.tsx` under `src/renderer/`
- Workbench composition: `workbench-shell.tsx` is the bootstrap-only root; `workbench-runtime.tsx` composes the content/execution sidebar, selected route, right/bottom panel hosts, command palette, and runtime Adapters. New state ownership belongs in the focused Window State, Catalog, Panel, Sidebar, Chrome, route, or runtime Module—not in either composition file.
- Workbench sidebar organizer state: `Pinned`, `Library`, `Projects`, and `Chats` header collapse state belongs to `sidebar.collapsibleSections` in `useWorkbenchProfilePreferences`, not to the sidebar content subtree. The real and floating sidebars can mount/unmount independently during explicit toggle and auto-reveal motion, so both consume the same `WorkbenchSidebar` projection and preference commands. `useWorkbenchSidebarChrome` owns hover/focus/resize motion; only settled collapsed/width values return to the preference owner. Pinned composition is fixed projection state, not a layout preference.
- Library navigation: `ProjectSessionSidebar` mounts `SidebarLibrarySection`; the legacy generic left-sidebar component is not the production owner. The section is a bounded lazy ownership projection with one composite `role="tree"`, roving focus, directional/Home/End/typeahead behavior, and active-path force inclusion. It shows top-level and Page-owned Page/Database Blocks; a multi-View Database may disclose its hosted Views. It never renders Data Sources or Database row Pages as tree children. `More` and the header book action open the full searchable Library workspace.
- Library mutations: New creates an Untitled Page or single-Source Database without a naming modal and opens it; an Untitled Page focuses its collaborative title. Context actions and the shared sidebar DnD builder use the same revisioned Library operations for ownership moves. Dropping or granting onto a Project always presents recursive `Read` versus `Read & write` confirmation, and navigation itself never creates a grant or changes a Database binding.
- Workbench app shell: top chrome controls must declare through the workbench `HeaderAction` registry so the mounted `WorkbenchRuntime` owns final ordering, `gap-1.5` spacing, measurement, and cross-panel reservation even when declarations come from separate components. Keep the bottom-panel toggle and side-panel toggle in the fixed global header, ordered bottom first and side second, with shared bottom-panel SVGs and an animated `header-shell-slot` width that follows the regular right-panel spring. Keep the active route title in the fixed global header center surface by reading the selected RouteScope's singular header atom, and keep the thread summary toggle registered as the center `HeaderAction` `local-thread-summary-panel-toggle`, rendered by the center inline rail in that same surface so it sits at the thread/right-panel boundary without creating an in-flow toolbar row. Keep right-panel tab creation plus expand/restore in the right-panel toolbar-height tab header, keep bottom-panel tab creation plus the plain `Close` X action in the bottom tab header, and implement right full-width mode by collapsing only the main thread viewport while the bottom panel remains visible. Keep the right-panel aside on `z-[41]` and the fixed global header above it so persistent bottom/side-panel toggles remain clickable in regular and full-width right-panel modes. The fixed-width right-panel content canvas must anchor to the aside's right edge while the overflow-clipping aside animates or resizes; shrinking or closing the regular panel reveals/clips content from the left so expand/restore and Card Stage's trailing toolbar actions remain fixed to the viewport edge instead of following the sash off-screen. Its target `width` is the sole reactive horizontal dimension; keep `min-width` statically at zero so an earlier target cannot survive as a second layout constraint after the sash shrinks. In full-width mode only, make the center header surface `aria-hidden` and `invisible`; the right header slot still uses `width: 0px` with its measured minimum so those toggles sit at the far-right edge while the panel tab header visually owns the rest of the top row. When the sidebar is collapsed and the right panel is full-width, the right-panel tab header must reserve the measured left titlebar width before its tab row; on macOS the collapsed fallback is `208px` (`82px` traffic-light safe area plus the compact rail). Panel tab headers must not be `draggable`; the fixed global header is the only native drag region for this top row. The fixed visible `header-shell-slot` rectangles and the right-panel tab header's start/end reservation wrappers still must be `no-drag` even when they stay `pointer-events-none`; these rectangles overlap clickable titlebar controls and must be excluded from Electron's native drag region. Right, bottom, and split-panel resize handles must start from `pointerdown`, call `setPointerCapture(pointerId)`, and finish through `pointerup` / `pointercancel` window listeners so body-attached Browser webviews cannot steal the drag stream. The right-panel expand/restore button and its trailing `right-panel-tab-bar-header-spacer` live in the tab header's after-list flow and use the measured right header width, not an absolute overlay. Thread pages use `data-app-shell-header-edge-scroll` on the fixed global header: it is true only for `thread-edge-scroll`, an effective main width of at least `96rem`, and no full-width right panel. Before that `96rem` container query applies, `thread-edge-scroll` keeps the main content frame below the fixed toolbar, uses the base thread/floating insets, and shows the guarded frame border. At `96rem` and wider, the frame top offset becomes `0px`, thread/floating top insets include toolbar height, and the full-bleed top fade can become visible. The physical main frame border is transparent only in the actual wide edge-scroll state without a right panel; do not add a separate absolute header-divider node such as `data-app-shell-main-content-header-divider`.

Projectless sessions render as normal chat rows in `Chats`, do not change `activeProjectId` when selected, and must not expose project-scoped DB/Card tab creation.

A Project Scene uses the same footer-only connector as a controlled Agent Dock on its fixed full-width stack, including unbound drafts and blank Sessions; it must not mount a second transcript body. `WorkbenchChromeLayout` owns geometry and the selected owner route supplies the anchor marked `data-right-panel-composer-overlay-host="true"`; the overlay mirrors that pane rect into a fixed body portal so panel overflow, zoom, and bottom-panel motion cannot clip or displace it. The selector renders no state words: its fixed leading slot shows the shared spinner for running, the shared blue dot for unread or attention, and a neutral dot for idle/read, matching the sidebar status language without duplicating its metadata rail. The rail inherits one 13px accessory inline inset, translucent input-surface tint, backdrop blur, and subtle edge so it stays legible over content without becoming a stack of independent cards. Changing the Agent Dock target atomically replaces the target-owned rail projection; it must not retain an exiting projection, carry expanded latest-turn state across targets, or animate sibling layout. Expanded latest-turn content remains inside the same rail surface and uses a 22.5rem reverse-flow viewport. Side chats, Terminal, Files placeholders, blank Session homes, and resuming attached Session pages keep the inline/no-composer paths instead.
- Right-panel composer presentation: model visibility as a discriminated policy, not accumulating booleans. `always` belongs to ordinary eligible Session overlays; `browser-auto` alone owns document-bottom/manual auto-hide; `controlled` belongs to Project Agent Dock persisted visibility and carries `none | activity | request` attention. Controlled hide makes the footer inert/unpresented, removes reserve, and leaves an accessible reveal handle; it must not stop a turn, clear a draft, or inherit Browser auto-hide. The floating footer reuses the primary composer state and actions through a presentation context; do not fork draft, attachment, permission, model, dictation, or submit logic. Empty and fitting floating composers use the 44px auto-single-line layout (`plus → prompt → context/model → permission → dictation → primary action`) with the `Do anything` placeholder; that branch does not mount an empty attachment tray. Determine fit from the prompt's measured longest unwrapped line and the compact input width left by the real leading/trailing controls, not from character count or explicit newline alone. Explicit line breaks, visual overflow, attachments, errors, or dictation promote the same shared adaptive footer to the normal Session composer shape: the prompt occupies a full-width first grid row, the standard Session leading controls remain left-aligned, and model/dictation/submit controls remain right-aligned in the second row. This measurement must remain stable in the expanded shape so deleting text, changing controls, or resizing the pane can return to compact without layout oscillation. The prompt editor owns the only overflowing scroll region. A fully expanded Browser adds `compact`, `compact-hovered`, and `expanded` presentation states: idle/hover stay at 384px and focus expands to the normal thread width. Other eligible tabs use the normal full-width floating presentation.
- Project Agent Dock worktree state is a projection, not component state. Resolve the newest exact `start-conversation` pending entry from the Main-synchronized collection by bound `projectSessionId`, stop projecting it as soon as the Session has a Thread, and register `draftId → projectSessionId → clientThreadId → threadId` aliases in one ThreadScope identity graph. Feed one blocked reason through both the footer model and `ThreadActionController`; disabling only the visible send button is not a sufficient duplicate-start boundary.

Capture-phase outside handlers update overlay-local state without unmounting, remounting, re-keying, or globally dismissing the original pointer target before its matching `click`. Focus may cross into an open Radix popper without collapsing the presentation. Dropdowns, popovers, and tooltips stay above the app shell through the floating UI layer.

True end-aligned center header actions, such as the fixed summary toggle, register through `HeaderAction` and render in the selected `WorkbenchRuntime` center trailing rail beside the selected route header content.
- Workbench left titlebar: sidebar toggle, app-window `Back` / `Forward`, and collapsed-sidebar `New chat` must declare through `HeaderAction` in the fixed global header's left slot. `WorkbenchChromeLayout` owns `--spacing-token-safe-header-left` and the measured left-slot width; never position left titlebar controls with fixed pixel overlays. Bottom-panel choosers stay Codex-only unless the action registry explicitly allows a Nodex tab kind there. - Panel tab context menus: feature-provided items come first, followed by a separator and generic `Close`, `Close other tabs`, and `Close tabs to the right` actions. - Panel tab sizing, rapid close, and dragging: a tab strip distributes all tabs equally from a zero flex basis within shared `90px` minimum and `160px` maximum widths; title length never gives one tab a larger share. The strip width clamps between the aggregate minimum and maximum, fills the unobscured row width between those bounds, and subtracts the measured in-row trailing-action width before distribution. Tab enter/exit geometry animates for 150ms while the strip retains the larger pre-exit tab count until all exits finish; reduced motion removes that entry/exit geometry. A tab uses 28px compact chrome with a 4px separator gutter, a 12px separator, and a title-local 28px truncation fade. The active close action is visible at rest; an inactive close action appears immediately on hover or focus-within, reserves 14px of end space in the same states, and therefore moves the title and its fade together rather than overlaying a second fixed gradient. Intersection sentinels own the real start/end strip fades, and active selection reveals its actual tab node without scrolling the page. Dominant vertical wheel input scrolls the strip horizontally while horizontal/equal-axis input remains native. Direct close-button and middle-click mousedown capture the target tab's `offsetWidth` and temporarily lock the whole row to that one width, preserving the next close target until the pointer leaves the tab row. Keep this state local to `AppShellTabs`; do not persist it, do not use it for context-menu bulk closes, and exit it before/when panel tab drag starts, tab-row wheel scrolling occurs, or a context menu opens. Bulk close dispatches from right to left. Rapid close must not influence which tab becomes active after close: `WorkbenchPanelController` routes close-button, middle-click, keyboard, and menu single-tab closes through same-leaf MRU, with right-neighbor then left-neighbor fallback only when MRU cannot answer. Tab dragging keeps the source in flow as an inert 20%-opacity placeholder and uses a measured, pointer-offset-preserving native preview with the tab's compact chrome inside a 70%-opacity bordered surface. Populated and empty tab rows share one non-layout-shifting insertion indicator: a centered accent rail with a hollow surface-colored endpoint. - Panel previews: Files and Browser can mount as renderer-local preview tabs before persistence, and single-click Kanban DB-view Card opens mount Card Stage as a right-panel preview in the nearest right leaf. ## State and Data Access
- API boundary: always go through `src/renderer/lib/api.ts`.
- Keep state component-local when it belongs to one mounted interaction: open menus, hover/drag geometry, upload progress, confirmation UI, and other disposable gesture state. Unmount is its cleanup policy; do not retain it merely to make task switching appear continuous.
- Open application modals through `src/renderer/lib/modal-registry.tsx` when their lifetime must be independent of a menu, row, route, or other trigger subtree. The App-scoped registry deduplicates by component identity, preserves the entry key when replacing props, stacks different modal components, and renders them through the one root host per renderer window. A dropdown-triggered modal opens from `onCloseAutoFocus` after the menu has closed. Keep short-lived confirmations local to their owning action boundary; that boundary must contain the trigger and its portaled descendants and stop pointer/click activation from reaching an interactive parent row.
- Use one Maitai App atom for renderer-window view state shared across routes, including Workbench layout aggregates and renderer-wide preferences. Use Thread, Route, or Composer scoped atoms only when presentation must survive an A → B → A remount for that exact identity. The scope hierarchy is App → Thread (20) → Route (20) → Composer (100), all inside the one renderer Jotai store; nested Jotai stores are forbidden.
- Use a Maitai persisted atom only for authored drafts or preferences that must survive a renderer restart. Every persisted value needs a versioned codec and an explicit synchronization policy; cross-window live application is a product decision, not an automatic consequence of storage. Never persist DOM nodes, editor instances, `File` objects, promises, runtime handles, or transport clients.
- Use TanStack Query for low-frequency main/server read models and mutation cache coordination. Keep Codex execution, Browser guests, Terminal sessions, collaborative Documents/Yjs, drag coordination, and approval authority in their deep runtime Modules; atoms may expose presentation projections or read-only external-store bridges but must not become a second writable authority.
- Low-frequency server state uses TanStack Query under `NodexQueryProvider`. Add keys in `src/renderer/lib/query-keys.ts` and query option helpers in `src/renderer/lib/query-options.ts`; feature hooks should compose those helpers instead of inventing component-local ad hoc query keys.
- Query client defaults are part of the renderer contract: `staleTime: 30_000`, `gcTime: 5 * 60_000`, query `retry: 1`, no focus/reconnect refetch, and mutation `retry: false`. Query Devtools are development-only and must stay hidden in Storybook.
- Query functions and mutation functions must still call the `lib/api.ts` transport facade. Do not call Electron bridges, browser fetch routes, or main-process channels directly from query code.
- Mutations should update the narrow cache when the server returns the complete next value, otherwise invalidate the exact affected key. Examples: project reorder writes `projects.list`; project create/update/delete invalidates `projects.list`; a forward Document-version restore resynchronizes the affected Document and refreshes its Card timeline; local-environment saves update the snapshot and invalidate that project's config list.
- Project-session hot paths use a window/detail cache split. `projectSessionSummariesQueryOptions(projectId)` requests the first `workspace:tasks:list` window only for projectless, expanded, or active scopes; `Show more` appends from its opaque `nextCursor`, and the selected task may be force-included through `project-sessions:get` without consuming window quota. The selected session, hover/focus prefetch, and explicit panel/tab operations use `projectSessionDetailQueryOptions(sessionId)` / `project-sessions:get` with the default 30s stale window. Do not restore `project-sessions:list`, eagerly map every Project into a query, or accumulate hidden full-scope arrays. Workbench mounts exactly one selected task page and each panel leaf mounts exactly one selected tab body. Query and deep runtime managers keep authoritative data/runtime state warm; DB View, Page Stage, Composer, and transcript restoration must use their explicit owners instead of hidden React trees.
- Codex sidebar state uses `queryKeys.codexSidebar.snapshot()` for the bounded overview and scope-keyed Workspace task-window queries for rows. The snapshot query first requests `codex:sidebar:snapshot({ refresh:false })`; it is not a complete Thread catalog or the external-thread discovery mechanism. `useSidebarThreadSyncModel` must not await a full app-server `thread/list` during mount or thread-open. It may schedule a low-priority `policy:"stale"` reconciliation, uses `policy:"stale"` on window focus/visibility regain, uses a focused visible 60s heartbeat, and debounces app-server host messages (`threadSummary`, title/delete, thread-start progress, and reconnect). Project/source changes use `policy:"force"` because cwd-to-project assignment may change. `project-sessions-changed` events are session container/link events only: they must not call `codex:sidebar:sync`; they mark affected `workspace:tasks:list` scopes for first-window refresh. Main-process `sidebarSyncUpdated` host messages are applied directly to the overview query and must not be routed back into another stale sync loop. Full project-session detail loads only for selected sessions or explicit panel/tab actions. If a sync result arrives before the task-window refresh callback is ready, queue the affected scopes and drain them when the callback is installed.
- Do not put a whole query or mutation result object in React dependency arrays. Destructure stable fields/functions such as `data`, `error`, `isPending`, `mutateAsync`, or `refetch`, and depend on those values.
- High-frequency external events may enter React state only at semantic transitions. Keep pointer/geometry samples in refs or MotionValues, and use `useDistinctState` for direct primitive transitions that must render. A functional state updater returning its current value is not an equivalent guard: React has already enqueued that update, so it can still participate in a pending commit/effect cycle.
- Reconcile effects that recompute an atom/store value from external data (Query results, the Project catalog) must be identity-idempotent. Derive query arrays through module-scope `select` functions (or `useMemo`) so effect dependencies are referentially stable, and route recomputed state through `replaceEqualDeep` (`src/renderer/lib/structural-sharing.ts`) so a semantic no-op returns the previous reference and bails out at the `Object.is` store boundary. An unconditional `{ ...prev, ... }` return in such an updater is a render-loop defect, not a style choice. Persist-on-state effects such as `useWorkbenchProfilePreferences` must debounce (see `WORKBENCH_PERSIST_DEBOUNCE_MS`) and flush on `beforeunload`/unmount.
- Keep Query out of high-frequency or optimistic ownership domains: `kanban-store`, local-conversation streaming manager state, terminal lifecycle, browser/webview manager state, drafts/forms, and localStorage-only preferences.

## Editor Patterns
- Keep custom editor behaviors in dedicated modules under `editor/`.
- Keep schema and extension composition centralized (`nfm-schema`, `toggle-list-schema`, extension helpers).
- `NfmEditor` must receive an explicit discriminated source. `legacy-snapshot` may use NFM `initialContent`, serialized-change debounce, blur flush, and external replacement. `collaborative-document` must use BlockNote's collaboration fragment/Awareness and must not install `initialContent`, serialize the whole body for persistence, or replace Blocks from a Card snapshot.
- Treat `BlockNoteEditor.prosemirrorView` as a mounted-view API. Tiptap returns a limited Proxy before mount and after unmount; reading `view.dom` from that Proxy throws even through optional chaining. Code that only needs the editor root must use BlockNote's lifecycle-safe `editor.domElement` and read it at interaction time instead of caching it during React render. Keep direct ProseMirror view access inside callbacks whose mounted-view ownership is explicit.
- Primary Card title and body share one surface-owned Y.Doc but keep local undo scopes. The rich-title contenteditable renders the validated Y.Text Delta through a DOM Adapter; React owns the surrounding toolbar/state but never reconciles the browser-mutated composition subtree. Intercept cancelable edits with a native `beforeinput` listener before the DOM changes—React's synthetic `onBeforeInput` is not an `InputEvent` boundary and cannot be cast into one. Non-cancelable/IME fallback reads both text and selection from live draft-DOM coordinates because committed segment offsets are stale after a browser mutation. Each writable mount has a distinct client/session origin; remote transactions do not enter its undo stack. The body UndoManager is registration/surface-owned and survives replaceable EditorView mount cycles; view cleanup removes only selection listeners, while extension/editor disposal destroys the manager.
- Start a managed Block drag only from the explicit BlockNote side menu after `blockDragStart` returns the authoritative root IDs. One window-local coordinator carries the source surface and logical parent to Document and Database targets. Same-surface reorder remains BlockNote-native; every cross-parent drop suppresses ProseMirror's cross-editor slice/text-caret path and submits one `BlockTransfer`. Nested targets arbitrate by the closest `.nfm-editor`, and Option/Alt is sampled again at drop.
- Add behavior regression tests next to editor helpers (`*.test.ts`).
- Preserve NFM round-trip compatibility when changing parser/serializer/adapters.
- For Card Stage rich-editor typing performance, follow `docs/card-stage-rich-editor-performance.md`.

## Styling Conventions
- A scroll container does not bound browser work: `max-height`, `overflow`, and line clamping can still leave every text, DOM, and accessibility node mounted. Never use those styles as the sole large-content strategy.
- Exact large source belongs in `VirtualizedTextViewer` through `LazyVirtualizedTextViewer`, which keeps selection and search while mounting only viewport-scale CodeMirror DOM. Rich Markdown, diff, JSON, and other tree-building representations must pass their feature budget before parsing; over-budget content uses exact source or an explicit domain rejection. Small inline previews may use `buildTextPreview`, but their full/copy action must read the canonical value lazily rather than silently truncating it.
- Global styles in `src/renderer/globals.css`.
- Hidden action chrome keeps visual reveal and sequential focus as separate contracts:
  - use hover, active, and open states for low-emphasis visual reveal by default
  - add keyboard-focus reveal only when the exact product surface requires keyboard operation for that hidden control; do not add `group-focus-within`, `focus-visible:opacity-100`, or `[:has(:focus-visible)]` just because an element is hover-revealed
  - hover-only secondary controls must stay out of sequential Tab order via `tabIndex={-1}` or be reachable through an already visible menu, native context menu, or command palette
  - machine/test selector controls must use `aria-hidden="true"` and `tabIndex={-1}` with no user-facing keyboard semantics
- Keep renderer CSS layered by ownership:
  - `src/renderer/styles/theme-source.css` owns author-maintained theme tokens, Tailwind theme declarations, and the CSS-side `--vscode-*` contract.
  - `src/renderer/styles/theme-codex-foundation.generated.css` owns the generated foundation layer for radius math, spacing, toolbar sizing, and window-scoped runtime overrides.
  - `src/renderer/styles/theme-codex-utilities.generated.css` owns the generated utility contract for shipped utility selectors and arbitrary/container utility coverage.
  - `src/renderer/styles/theme-codex-contract.generated.css` owns the generated canonical `--color-token-*` contract and `--vscode-*` window contract.
  - `src/renderer/styles/theme-token-bridge.css` owns only Tailwind-facing authored aliases that are not part of the generated contract or generated foundation layer.
  - `src/renderer/styles/theme-codex-surface.generated.css` owns the generated component/global surface rules.
  - `src/renderer/styles/theme-utilities.css` owns authored Nodex-local utilities that are intentionally outside the generated utility contract.
  - `src/renderer/styles/theme-surface.css` owns authored surface rules and global renderer CSS.
  - `src/renderer/lib/codex-theme-variant.ts` owns the runtime semantic theme bridge that injects derived foreground/control/border/panel/editor variables onto `document.documentElement`, plus document-scoped runtime overrides such as `--cursor-interaction` on both `documentElement` and `body`.
  - Electron window material flows from main-process backdrop state into root classes and attributes: `data-codex-window-type`, `data-window-type`, `data-codex-os`, `data-codex-window-chrome`, `compact-window`, and `electron-opaque`. Keep normal Electron `body` background transparent; sidebar/background panels own their own tokenized material, while `electron-opaque` is the only root/body opaque-surface switch.
  - Electron shell typography must flow through the Codex `--vscode-font-family` / `--vscode-font-weight` contract on `body`, with `--vscode-font-weight: 430` and antialiased WebKit text smoothing. Do not locally compensate for perceived sidebar weight with per-row `font-weight` classes; keep sidebar rows on inherited shell typography and token foregrounds.
  - Reuse semantic chip/badge patterns for priority/estimate/status.
  - Avoid duplicating visual rules across board and toggle-list surfaces.
- Follow the renderer composition order:
  - normalize raw runtime data into stable renderer-facing item/view schemas first

  - settings search rows should preserve the Codex row/input token contract (`h-token-button-composer`, `px-row-x`, `ps-8.5`, `data-list-navigation-item`, `bg-token-list-hover-background`)
  - settings sidebar vibrancy is owned by the same transparent Electron window material as the normal sidebar; individual settings sections should render only the `main-surface` content pane
  - when adjusting the rail, prefer the shared rail class family (`window-fx-sidebar-surface`, `px-row-x`, `py-row-y`, `icon-xs`, `icon-sm`, `bg-token-list-hover-background`) over local approximations
  - each settings section should render as its own page surface and own its own loading/empty/error state where needed
- Keep renderer forms boundary-led: use TanStack Form with a colocated zod schema module when a form has structural validation, type coercion, or multi-field constraints. For simple single-field inputs, keep local state and a submit-time guard instead of introducing a separate schema module.
- For thread search, project stable user/assistant search units in the view model and attach them to rendered blocks; do not implement `Find in thread` by scraping arbitrary DOM text from the whole turn.

## Component SOP
- Start from existing semantics, not from JSX. New UI behavior should usually begin in a projector, bucketizer, normalizer, or other renderer-facing adapter before touching leaf components.
- Keep leaf renderers dumb. Message/tool/request components should consume already-derived props such as lane membership, action eligibility, placeholder state, or copy text instead of recomputing those rules locally.
- Keep one canonical lane per semantic role. Final assistant content, leading user prefix actions, exploration groups, pending-request lanes, and diff lanes should each be derived once and rendered once.
- Keep transcript-special rows dedicated. Items such as context compaction, automatic approval review, and multi-agent activity should render through their own leaf components instead of falling back to generic system banners. Multi-agent headers include the shared subagent glyph, and row links resolve friendly names from receiver metadata or parent child memberships before falling back to raw thread ids.
- Keep poor-network reconnect in the transcript, not in shell resume state:
  - retryable transport/turn errors should materialize as `streamError` transcript items with expandable details
  - non-retryable turn failures should materialize as `systemError` transcript items
  - do not reuse `resumeState` placeholders or shell overlays for the `Reconnecting... 2/5` feature
- Prefer rendered behavior over source-looking class strings. If runtime behavior and an apparent source token disagree, treat the rendered CSS/output as authoritative.
- Keep component chrome subdued. Secondary actions should stay small, low-emphasis, and hover-revealed unless the product surface makes them primary. Hover reveal does not imply sequential keyboard focus.

## Frontend Testing
- Run targeted tests while iterating: `pnpm test src/renderer/...`
- Run isolated UI harness: `pnpm run dev:storybook`
- Treat Storybook as part of the UI contract. When adding or changing any user-visible UI, update or add the focused stories in the same change instead of leaving Storybook behind.
- Keep Storybook scenes canvas-first: use story variants, `args`, and `argTypes` for presets and controls instead of rendering custom preset/control sidebars inside story pages.
- Keep Storybook scenes production-backed: thread and card-stage stories should build state from the same projection/helpers used by shipped UI instead of hand-authoring parallel fake view models.
- Keep shared UI stories focused. Cover `dropdown`, `popover`, `tooltip`, `button`, `dialog`, and `settings` primitives with explicit regression states such as compact/icon-only triggers, long labels, search rows, flyout submenus, and compact-control tooltips instead of relying on a single catch-all gallery.
- Keep embedded kanban control stories focused on the actual regression surfaces: toggle-list rules/inline controls, card-ref floating toolbars, inline property strips, command-palette filters, and db-view toolbar rules should each have their own visible harness stories.
- Keep `settings/environments` stories flow-complete: workspace root, multi-config project rows, summary, edit, parse error, create-new, and environment-variable popover states should all be separately reproducible.
- Keep selector stories split by feature. Branch and environment selectors should not share one mixed story page; cover default, empty, busy/loading, long-label/path, and icon-sizing states independently.
- Keep menu-driven stories open by default through story-only harnesses. Context menus, sidebar menus, and project manager popovers should render their open state directly instead of asking the reviewer to right-click or click to reveal the actual surface.
- Current thread stories live under `src/renderer/features/local-conversation/view/` for composed stage scenarios and under `src/renderer/features/local-conversation/view/shared/` for focused transcript-special, tool, and request leaf stories. Keep transcript-special surfaces such as reasoning, todo lists, automatic approval review, and multi-agent activity in the transcript-special stories instead of forcing them into tool-call stories.
- Keep tool-call stories scoped to actual Codex tool families. Transcript-special surfaces that happen to originate from tool-like raw items still belong in transcript-special stories once the projector gives them their own semantic lane.
- Default renderer component tests to the repository's pnpm-driven Vitest jsdom
  runtime with `@testing-library/react`; use Vitest Browser Mode only when the
  contract depends on real layout, selection, focus, or pointer behavior.
- Assert user-visible structure, labels, and behavior through rendered DOM queries; keep `data-testid` and raw class checks as fallback tools, not the default.
- Reserve HTML-string or server-render assertions for cases where serialized markup is the actual contract.
- Do not add source-string tests that only verify implementation text inside a file.
- Prioritize parser/editor and hook tests for regression safety.
