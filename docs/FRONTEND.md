# Frontend

## Stack
- React 19 + TypeScript (`strict`)
- Tailwind CSS + local UI primitives in `src/renderer/components/ui/`
- BlockNote editor for rich card descriptions
- Atlassian Pragmatic Drag and Drop for board drag-and-drop

## Structure
- App shell: `src/renderer/app.tsx`
- Domain components: `src/renderer/components/kanban/`
- Active local conversation renderer: `src/renderer/features/local-conversation/`
- Editor subsystem: `src/renderer/components/kanban/editor/`
- Shared hooks/helpers: `src/renderer/lib/`
- NFM conversion/parsing: `src/renderer/lib/nfm/`
- Storybook workspace: `packages/storybook/` with colocated `*.stories.tsx` under `src/renderer/`
- Workbench shell: `src/renderer/components/workbench/workbench-shell.tsx` renders the Codex-style projects sidebar with pinned chats, project folders, projectless `Chats`, a session thread page, plus independent right and bottom panels for session-attached tabs.
- Workbench app shell: top chrome controls must declare through the workbench `HeaderAction` registry so `WorkbenchShell` owns final ordering, `gap-1.5` spacing, measurement, and cross-panel reservation even when declarations come from separate components. Keep the bottom-panel toggle and side-panel toggle in the fixed global header, ordered bottom first and side second, with shared bottom-panel SVGs and an animated `header-shell-slot` width that follows the regular right-panel spring. Keep the active thread title in the fixed global header center surface through `ThreadHeaderPortalProvider`, and keep the thread summary toggle in that same center surface's trailing rail so it sits at the thread/right-panel boundary without creating an in-flow toolbar row. Keep right-panel tab creation plus expand/restore in the right-panel toolbar-height tab header, keep bottom-panel tab creation plus the plain `Close` X action in the bottom tab header, and implement right full-width mode by collapsing only the main thread viewport while the bottom panel remains visible. Keep the right-panel aside on `z-[41]` and the fixed global header above it so persistent bottom/side-panel toggles remain clickable in regular and full-width right-panel modes. In full-width mode only, make the center header surface `aria-hidden` and `invisible`; the right header slot still uses `width: 0px` with its measured minimum so those toggles sit at the far-right edge while the panel tab header visually owns the rest of the top row. When the sidebar is collapsed and the right panel is full-width, the right-panel tab header must reserve the measured left titlebar width before its tab row; on macOS the collapsed fallback is `208px` (`82px` traffic-light safe area plus the compact rail). Panel tab headers must not be `draggable`; the fixed global header is the only native drag region for this top row. The fixed visible `header-shell-slot` rectangles and the right-panel tab header's start/end reservation wrappers still must be `no-drag` even when they stay `pointer-events-none`; these rectangles overlap clickable titlebar controls and must be excluded from Electron's native drag region. Right, bottom, and split-panel resize handles must start from `pointerdown`, call `setPointerCapture(pointerId)`, and finish through `pointerup` / `pointercancel` window listeners so body-attached Browser webviews cannot steal the drag stream. The right-panel expand/restore button and its trailing `right-panel-tab-bar-header-spacer` live in the tab header's after-list flow and use the measured right header width, not an absolute overlay. Thread pages use `data-app-shell-header-edge-scroll` on the fixed global header: it is true only for `thread-edge-scroll`, an effective main width of at least `96rem`, and no full-width right panel. Before that `96rem` container query applies, `thread-edge-scroll` keeps the main content frame below the fixed toolbar, uses the base thread/floating insets, and shows the guarded frame border. At `96rem` and wider, the frame top offset becomes `0px`, thread/floating top insets include toolbar height, and the full-bleed top fade can become visible. The physical main frame border is transparent only in the actual wide edge-scroll state without a right panel; do not add a separate absolute header-divider node such as `data-app-shell-main-content-header-divider`.
- Workbench session rows and rename entry points must render the service-derived `ProjectSession.displayTitle`, not `noThreadFallbackTitle`, for attached Codex sessions. `noThreadFallbackTitle` is only the blank-session/final fallback label. Generated/manual title changes should appear as normal text re-rendering in the sidebar and fixed header; do not add title-specific spinners, badges, toasts, fade animations, or layout transitions. Projectless sessions render as normal chat rows in `Chats`, do not change `activeProjectId` when selected, and must not expose project-scoped DB/Card tab creation.
- App shell layers: use the named constants in `src/renderer/lib/app-shell-layers.ts` instead of scattering literal z-index utilities. The current shell contract is right-panel shell `z-[41]`, normal browser webview layer root `42`, global header `z-[42]`, right-panel composer overlay `z-[42]`, floating left sidebar panel `z-[43]`, and floating UI poppers `z-50`. Do not fix click interception bugs by raising chrome to `z-[999]` or by adding a full-surface `pointer-events-auto` overlay above the right panel; fix DOM ownership, pointer-event scope, or event timing instead.
- Right-panel composer overlay: attached root threads render the normal thread composer as a floating overlay when the right panel is full-width and the active right-panel tab is `review`, `browser`, `db_view`, or `card_stage`. `WorkbenchShell` owns the full-width right-panel portal host marked `data-right-panel-composer-overlay-host="true"`, and `LocalConversationFooter` owns the overlay DOM, latest-turn preview, above-composer portals, composer shell, pointer-outside collapse, and `--right-panel-composer-overlay-*` reserve variables. Side chats, Terminal, Files placeholders, blank new-thread homes, and resuming attached threads must keep the inline/no-composer paths instead.
- Right-panel overlay pointer handling: overlay roots must remain `pointer-events-none`; only the stable visible composer subtree may become `pointer-events-auto`. Capture-phase outside handlers must only update overlay-local state and must not unmount, remount, re-key, or globally dismiss the original pointer target before the matching `click` event. Dropdowns, popovers, and tooltips stay above the app shell through the floating UI layer, while global tooltip dismissal must close popper state without remounting trigger subtrees.
- Active thread header content uses the Codex two-column grid `grid-cols-[minmax(0,1fr)_auto]`: the left/start row contains the max-320px truncated title followed immediately by start actions such as `Thread actions`, without a `w-full` or `flex-1` spacer on the title. The trailing row is reserved for true end-aligned controls such as the fixed summary rail.
- Workbench left titlebar: sidebar toggle, app-window `Back` / `Forward`, and collapsed-sidebar `New chat` must declare through `HeaderAction` in the fixed global header's left slot. `WorkbenchShell` owns `--spacing-token-safe-header-left` and the measured left-slot width; never position left titlebar controls with fixed pixel overlays. Expanded sidebar reserves the sidebar width and orders `Hide sidebar`, `Back`, `Forward`; collapsed sidebar reserves the measured traffic-light-safe rail and orders `Show sidebar`, `Back`, `Forward`, and `New chat`. On macOS the safe header constant is `82px`, and the collapsed fallback rail is `208px` total. The compact New chat titlebar button uses the 16px edit/new-chat glyph while preserving the accessible label. The Back/Forward controls use the exact toolbar ghost button contract, `ArrowLeft icon-xs` for Back, the same icon with `-scale-x-100` for Forward, and `disabled:opacity-40`. Their enabled state and execution must come from the `WorkbenchShell` history stack, not `App`'s legacy stage-rail history. Do not wire these app-window controls to browser-sidebar `webContents.canGoBack` / `goBack` / `goForward`.
- Panel chooser behavior: keep empty-panel actions and panel-header plus menus driven from the same target-aware `PANEL_NEW_TAB_ACTIONS` registry in `WorkbenchShell`. The visible Codex-parity option order is `Review`, `Terminal`, `Browser`, `Files`, and `Side chat`, filtered by target panel and singleton availability. Empty-panel choosers use the row-stack contract (`p-2`, centered `max-w-xl`, `gap-1 px-panel`, full-width `min-h-10` secondary-background rows, `icon-xs` icons, `text-sm font-normal` labels, compact right-aligned shortcut labels). Right-panel choosers append a separator plus Nodex-only `DB View` and `Card Stage` rows after the Codex list. `DB View` creates or focuses the active session project's DB tab directly until that project already has a DB tab, then opens the shared move-to-style DB destination picker so another project DB can be selected; Card Stage always opens the card-scoped picker, with the active session project's card results grouped before other projects. Bottom-panel choosers stay Codex-only unless the action registry explicitly allows a Nodex tab kind there. Keep `Timeline` hidden until a first-class Nodex tab kind is implemented. `review` is a session singleton and must be filtered/focused consistently across both right and bottom panels; DB View is one tab per target project, and Browser is multi-tab.
- Panel tab context menus: feature-provided items come first, followed by a separator and generic `Close`, `Close other tabs`, and `Close tabs to the right` actions. Disable `Close other tabs` unless another closable tab exists in the same leaf, and disable `Close tabs to the right` unless a later closable tab exists. Browser tab menus keep `New tab to the right`, `Reload`, and `Duplicate` before this generic close block. Move and split actions can remain below the close block when available.
- Panel tab rapid close: direct close-button clicks and middle-click closes may temporarily lock the current tab row's measured item widths so the next contiguous closable tabs keep the same close target under the pointer. Keep this state local to `AppShellTabs`; do not persist it, do not use it for context-menu bulk closes, and exit it before/when panel tab drag starts, tab-row wheel scrolling occurs, or a context menu opens. Rapid close must not influence which tab becomes active after close: `WorkbenchShell` routes close-button, middle-click, keyboard, and menu single-tab closes through same-leaf MRU, with right-neighbor then left-neighbor fallback only when MRU cannot answer. The temporary widths must not change `data-panel-tab-id`, `no-drag` ownership, Pragmatic Drag and Drop source data, or the non-layout-shifting insertion marker contract.
- Panel previews: Files and Browser can mount as renderer-local preview tabs before persistence, and single-click Kanban DB-view card opens mount Card Stage as a right-panel preview in the nearest right leaf. Keep one italic preview per leaf; the next preview open in that leaf replaces the previous one. Double-clicking a Kanban card should open Card Stage durably, while double-clicking a preview tab label should pin that preview. Keep previews out of shared SQLite state until pinning/interacting runs the normal `project-session-tabs:create` flow. Card Stage previews must reuse their durable-compatible tab id and retained wrapper identity when pinned so the Card Stage body does not remount. Card Stage close/delete controls must mark their targets with `data-app-shell-preview-pin-suppressed="true"` so closing or deleting an unpinned preview does not persist it first. Explicit Card Stage picker/action opens remain durable and should not be added to generic previewable add-menu behavior.
- Side chats: keep Side chat as a renderer-local tab family (`sidechat-loading:*` and `sidechat:*`) rather than a previewable durable tab kind. Side-chat creation flows through `useCodexAppServerControl().startSideChat`, close flows through best-effort `discardSideChat`, and expired states render the exact side-chat expired panel with a recreate action. Do not add side-chat ids to project-session tab ordering, window-session restore snapshots, project thread summary lists, or archive/title flows.
- Workbench sidebar: project/session sidebar chrome lives in `src/renderer/components/workbench/codex-sidebar.tsx`; use the shared row classes and markers (`app-shell-left-panel`, `nav[role=navigation][aria-label="Automation folders"]`, `data-app-action-sidebar-section*`, `data-app-action-sidebar-project-*`, `data-app-action-sidebar-select-project`, `data-app-action-sidebar-thread-*`, `data-app-action-sidebar-thread-active`, `data-app-action-sidebar-thread-host-id`, `data-app-action-sidebar-thread-id`, `data-app-action-sidebar-thread-kind`, `data-app-action-sidebar-thread-pinned`, `data-app-action-sidebar-thread-unread`, `data-app-action-sidebar-thread-pin-session`, `data-app-action-sidebar-thread-archive`, `data-thread-title-trigger`, `data-thread-title`, `h-token-nav-row`, `py-row-y`) instead of local project-row styling, and keep project folder selection inside the project row actions menu. The sidebar has one `Pinned` section; pin organization is controlled from the `Projects` section header's `Project sidebar options` menu, where `Organize pins` opens a single-choice submenu persisted in sidebar prefs, with `By project` as the default and `Manual order` as the compatibility mode. Hide the entire `Pinned` section header when the current projection has no standalone pinned chats and no pinned project folders to show. In `By project`, project-scoped pinned chats render at the top of their project subtree, pinned project folders stay in `Pinned` with their pinned chats inside that subtree, projectless/orphan pinned chats remain standalone in `Pinned`, `Projects` renders unpinned project folders, and `Chats` renders projectless non-pinned chat rows. In `Manual order`, all pinned chats render as standalone rows in `Pinned` before pinned project folders, and project subtrees exclude those pinned rows. The `Projects` section header owns keyboard-revealed hidden action buttons in this fixed order: the first project-group action is hidden when not applicable, becomes `Collapse all` only when more than one visible project folder is expanded, and becomes `Reopen previous` after that collapse if previously expanded visible folders can be restored; `Project sidebar options` opens the compact project-sidebar menu: `Archive all chats` and unsupported organize/sort targets are disabled mock items, `Organize pins` is the live pin-organization selector, and current `Manual order` is shown as selected in the sort submenu; `Add new project` opens the supported project creation menu with `Start from scratch` and `Use an existing folder`, both using the same folder-plus menu glyph. Session row root padding follows the shared density contract: horizontal `px-row-x` belongs on the inner full-width row content, not on `CODEX_SIDEBAR_THREAD_ROW_CLASS`; the title span remains `min-w-0 flex-1 truncate select-none` and `draggable={false}`. New projects start with an ordinary pinned `Database View` session at the top of pinned rows or, in `By project`, at the top of that project subtree; newly created blank project chats appear at the top of normal project rows below pinned sessions and above older normal chats. Project group headers are disclosure controls only: clicking or pressing Enter/Space on a project header folds/expands that group and must not switch the active project/session; session rows perform project/session switching. Project headers use the shared folder SVGs from `src/renderer/components/shared/icons.tsx`: 16px closed folder while collapsed and 16px open folder while expanded, with the shared down-chevron path rotated by `-rotate-90` when collapsed. Project headers are sortable under the sidebar-level `DndContext`, use `sidebar-group:{projectId}` sortable ids, expose `role="button"`, `tabIndex=0`, `aria-roledescription="sortable"`, the dnd-kit `aria-describedby` live-region hook, and a hidden `data-app-action-sidebar-select-project` button for selector parity. Project group drag motion must be vertical-axis only and the sortable row style must use translate-only transforms, not scale, so previews slide between slots without horizontal drift or resizing to the target slot. Project and project-thread lists use the shared sidebar pagination helper in `src/renderer/lib/codex-sidebar-pagination.ts`: project folders start at 5, project child chats start at 5, `Show more` adds `$D = 10` rows per page, `Show less` resets to 5, active overflow items stay forced-visible, and archive-suppressed keys filter before slicing. Project headers show the same keyboard-revealed disclosure chevron after the label as titled sidebar section headers, rotating it for collapsed groups. ## State and Data Access
- API boundary: always go through `src/renderer/lib/api.ts`.
- Low-frequency server state uses TanStack Query under `NodexQueryProvider`. Add keys in `src/renderer/lib/query-keys.ts` and query option helpers in `src/renderer/lib/query-options.ts`; feature hooks should compose those helpers instead of inventing component-local ad hoc query keys.
- Query client defaults are part of the renderer contract: `staleTime: 30_000`, `gcTime: 5 * 60_000`, query `retry: 1`, no focus/reconnect refetch, and mutation `retry: false`. Query Devtools are development-only and must stay hidden in Storybook.
- Query functions and mutation functions must still call the `lib/api.ts` transport facade. Do not call Electron bridges, browser fetch routes, or main-process channels directly from query code.
- Mutations should update the narrow cache when the server returns the complete next value, otherwise invalidate the exact affected key. Examples: project reorder writes `projects.list`; project create/update/delete invalidates `projects.list`; history undo/redo updates `history.recent(projectId, sessionId)` and invalidates the affected board; local-environment saves update the snapshot and invalidate that project's config list.
- Codex sidebar state uses `queryKeys.codexSidebar.snapshot()` and `queryKeys.codexSidebar.pinnedThreads()`. The snapshot query must first request `codex:sidebar:snapshot({ refresh:false })` and remain a low-frequency SQLite read model cache; it is not the external-thread discovery mechanism. `useSidebarThreadSyncModel` must call `codex:sidebar:sync({ policy:"force", reason:"mount" })` after mount, `policy:"stale"` on window focus/visibility regain, a focused visible 15s heartbeat, and debounced app-server host messages (`threadSummary`, title/delete, thread-start progress, and reconnect). Project/source changes use `policy:"force"` because cwd-to-project assignment may change, while session-only changes use `policy:"read"`. Main-process `sidebarSyncUpdated` host messages are applied directly to the sidebar snapshot query and must not be routed back into another stale sync loop. Sync results that report `changedProjectIds` or `projectlessChanged` must refresh the matching `project-sessions:list` caches even when those projects are inactive; `WorkbenchShell` must not add a separate active-project-only session listener. If a sync result arrives before the session refresh callback is ready, queue the affected scopes and drain them when the callback is installed. Pinned-thread reads intentionally use short freshness (`5s`) and window-focus refetch to match Codex sidebar behavior.
- Do not put a whole query or mutation result object in React dependency arrays. Destructure stable fields/functions such as `data`, `error`, `isPending`, `mutateAsync`, or `refetch`, and depend on those values.
- Keep Query out of high-frequency or optimistic ownership domains: `kanban-store`, local-conversation streaming manager state, terminal lifecycle, browser/webview manager state, drafts/forms, and localStorage-only preferences.
- Board state: `useKanban` uses a shared `kanban-store` optimistic journal (`baseBoard + pending/local overlays`) with LWW conflict superseding, rollback-on-failure, and store-derived cross-view sync. The store owns `BoardSummary`, not full `Board`; `cardIndex` entries must not contain full `description`.
- Card bodies: load full `Card.description` only through `card-detail-store`, `card:get`, or `cards:details:get` for selected/visible cards. Card Stage hydrates the active card detail before editing; toggle-list, inline toggle-list, and `cardRef` projections first compute visible ids from summary state, then batch-hydrate those cards. Board/list/calendar/card picker/command-palette default paths should stay summary-only.
- Command palette root mode must be built from current session, panel, tab, and settings shell actions. Root mode searches command rows only; chat and card search live in explicit modes opened by their own shortcuts or by root-mode mode-switch rows, while the file-search shell remains a development-only parity placeholder until it has a real backend. Unsupported Codex-parity actions may appear only in development builds as disabled rows with a `Mock` badge, gated from the catalog with `import.meta.env.DEV`; production command catalogs must not include mock rows. Nodex-only shell actions such as DB View belong in the closest matching command group.
- Command palette icons should come from the reference icon manifest in `src/renderer/components/workbench/command-menu-reference-icons.tsx` before using local or Lucide fallbacks. The exported `COMMAND_MENU_REFERENCE_ICON_MANIFEST` records extracted asset source paths and fallback status so parity gaps are visible.
- Reference-only menu actions must follow the same rule as command-palette mocks: production models do not include them, while development and Storybook can opt in with explicit `showMockActions` / `showReferenceMocks` inputs and visible `Mock` badges. Keep real but context-disabled actions visible without a `Mock` badge, and gate runtime defaults with `import.meta.env.DEV` instead of a broad feature-flag framework.
- Card search: local summary fields can be searched immediately in cards mode. Description search must go through `cards:search`, which returns ids and bounded excerpts; do not load every project's full board to build a renderer description index. Card filters belong to cards mode and should not affect chat or command results. NFM `@` card mentions must reuse the command-palette card item shape, MiniSearch index, and description-hit merge selector instead of applying a second substring filter over suggestion rows.
- Command palette chat search: chat metadata must come from the global sidebar snapshot or an equivalent all-thread read model, including projectless/sessionless sidebar chats. Content matches must go through the bounded `codex:threads:palette:search-content` IPC path backed by Nodex's local worker-owned FTS5 index. Search IPC must be read-only against the current index; sidebar/list refresh may enqueue throttled worker backfill separately. `Send to chat` and NFM `@` thread mentions must reuse this renderer chat-search substrate for candidate loading, MiniSearch ranking, and content-snippet merging; destination-specific code may only add context preference, footer, insertion, or send-target behavior. User-facing labels should say `chat`; internal protocol and storage names may still say `thread`. Do not call app-server `thread/search`, scrape mounted transcript DOM, load every thread transcript into the renderer, trigger backfill from search, or rebuild content fuzzy indexes on the Electron main process.
- Card updates use typed mutation control flow: `updated | conflict | not_found | error` instead of treating stale-write conflicts as generic exceptions.
- Successful card-update acknowledgements are summary-only and must not carry full `description`; renderer code should merge the returned `CardSummary` into board state and update active detail state from the submitted local draft plus the acknowledged revision. Fetch full bodies only through explicit detail hydration.
- On `conflict`, keep optimistic journal semantics: supersede conflicting overlays, refresh base board, and let surface-specific UX decide recovery (`Card Stage` inline banner with `Reload Latest` / `Overwrite Mine`).
- Full board fetches are not a renderer API. New renderer code should use `board:summary:get` plus explicit card detail hydration; adding a broad full-board read path is a regression.
- History/undo: `use-history.ts`.
- Project lifecycle: `use-projects.ts`.
- SSE/IPC updates are centralized in API subscription helpers.
- Live workbench window state is narrow and local: active project, active session, and transient focus history can live in `sessionStorage`/window-session snapshots for continuity. App-window Back/Forward history uses `sessionStorage` key `nodex-workbench-shell-navigation-history-v1` and stores only shell-visible project/session/panel context.
- Shared project-session structure is SQLite-owned: sessions, project/projectless ownership, project-local archive/unread state, legacy pin mirrors, right/bottom panel state, session tab records, tab ordering, tab state, and session-thread attachments load through the project-session IPC/HTTP APIs rather than renderer-local reducers. Global thread pin state for attached chats comes from `codex_pinned_threads` through the Codex sidebar APIs.
- Cold-launch resume is window-session-owned in Electron: the main process stores profile-local window sessions under `userData`, renderer bootstrap applies the assigned session layout before mounting, and new windows seed from explicit layout input, the last-focused window layout, or the default workbench layout.
- Terminal: `terminal-session-store.ts` owns renderer terminal session snapshots, active metadata, pending writes, resize dedupe, and 16k buffer truncation over the `terminal-*` IPC protocol. `use-terminal.ts` mounts `@xterm/xterm` with Clipboard/Fit/WebLinks add-ons, CSS-variable terminal theme extraction, concrete editor-font typography from `terminal-typography.ts`, Codex terminal key handling, and the window-zoom mouse coordinate patch. Terminal typography keeps the Codex editor font as the primary face and appends the bundled `Symbols Nerd Font Mono` as a symbol-only fallback for Powerline/Nerd Font glyphs. Terminal scrollbars are xterm-owned, not generic `scrollbar-token`: hide the native `.xterm-viewport` scrollbar and style xterm 6's `.xterm-scrollable-element > .scrollbar > .slider` as a narrow rounded token thumb so Electron's classic scrollbar gutter does not render as a square 14px block. Terminals are session panel tabs; Card Stage can request a terminal, but cards do not own terminal tab config or PTY identity. New session terminal tabs start in the attached thread cwd when present, otherwise the owning project workspace path, otherwise the terminal process default.
- Session tab bodies should stay reusable: DB view hosts, Card Stage, terminal, and Browser surfaces mount behind `ProjectSessionTab.kind`; do not rebuild separate shell-specific versions of those features. Durable Card Stage tabs should stay mounted in stable app-shell body wrappers while their leaf is mounted, with only the visible Card Stage allowed to own shared close/persist/session-snapshot refs; inactive retained Card Stages are hidden and persist pending editor changes when deactivated. Browser tabs use the shared browser-sidebar feature module, stay separate from app-window Back/Forward history, and must route page navigation through browser-sidebar IPC instead of direct renderer `<webview>` method calls. Browser webviews are manager-owned: one body-attached manager root owns the `<webview>` for the whole browser-tab lifetime, while React tab bodies provide only placeholder geometry and visibility signals. Switching tabs, collapsing panels, or remounting React shells must reposition/background that stable manager root rather than reparenting, closing, or mounting the guest under `hidden` / `display:none`; only explicit Browser close/reset teardown may destroy the guest. Because the webview root is fixed under `document.body`, Browser tabs must resample placeholder `getBoundingClientRect()` from the owning right/bottom panel motion value as well as ResizeObserver/window events, so panel open/close transitions cannot leave the webview painted at a stale midpoint. Keep Browser chrome on the compact panel contract: a `h-toolbar-pane` toolbar row, shared square icon buttons, centered idle address input with skip-commit action targets, collapsed screenshot/comment actions on blank tabs, full-bleed responsive webview hosting, and the narrow `Local` blank-tab server list with storage-backed show/sort preferences.
- Active conversation UI: keep Codex host-message ingestion in the singleton external store under `features/local-conversation/`, subscribe through per-thread selectors, then derive renderer-only projection data in `features/local-conversation/projection/*`. Keep transcript projection, composer-shell aggregation, search-unit derivation, turn-request stitching, and background-activity ordering upstream of JSX.
- Keep active conversation UI ownership inside `features/local-conversation/view/*` and `features/local-conversation/view/shared/*`. Do not reintroduce a second workbench thread renderer path outside that feature.
- Thread user-message navigation rail is renderer-derived only. Build rail items from `VisibleConversationTurnEntry[]` through `projection/thread-user-message-navigation-items.ts`, not from a backend navigation API. All rendered `userMessage` blocks must receive stable search-unit keys in `${turnId}:user:${index}` order, including empty text and attachment-only messages; content search should still match only through non-empty `ThreadSearchUnitModel.text`.
- The rail DOM contract is part of the thread body contract: `nav[aria-label="User messages"]` is portaled into the thread scroll shell target (`data-thread-user-message-navigation-portal-target="true"`) as a sibling of the scroll viewport, not into the transcript/content portal lane. Row buttons carry `data-thread-user-message-navigation-item-id`, and targets are resolved through `[data-content-search-unit-key]`. The rail should render only when the measured left gap from the scroll viewport to `[data-mcp-app-portal-target="true"]` is at least `48px` (`12px` rail inset + `36px` row width), matching Codex Electron. Current-row tracking must derive from those search units but observe the nearest `[data-turn-key], [data-content-search-turn-key]` container; do not regress to observing only the small search-unit leaf. User bubbles and attachment pills must keep `data-user-message-bubble="true"` / `data-composer-attachment-pill="true"` so navigation highlight can pulse the actual message surface.
- Thread rail and search navigation must stay on the shared bottom-distance scroll substrate. The thread viewport uses `flex-col-reverse`, so bottom is native `scrollTop = 0` and older content can require negative native `scrollTop`; callers must not compute `targetRect.top - scrollRect.top + scrollTop` or clamp old-message targets to `0`. Missing virtualized rail/search targets should call `LocalConversationVirtualizedTurnListApi.scrollToKey(turnKey, targetResolver)` to expand the rendered window before querying again, and exact mounted targets should be brought into view through `LocalConversationThreadScrollController.scrollElementIntoView` or native `scrollIntoView`. Clicks use smooth behavior for the final target scroll; pointer scrub uses instant behavior. Content search reveal is a two-step contract: `ensureVisible(match, { signal })` may uncollapse and mount the target, then `activate(match)` only owns marks and the active-mark center scroll. New active matches must abort the previous reveal so stale long-transcript navigation cannot win after the user moves to another result.
- Thread virtualization is bottom-distance-native end to end. `local-conversation-turn-virtualization.ts` owns the pure layout model (`topOffsetsPx`, `bottomOffsetsPx`, `heightsPx`, `totalHeightPx`, `turnKeys`, `turnIndexByKey`) and range helpers; the mounted UI stays split into a core virtualized list and a thread-scroll wrapper. The core list owns fixed-height flow layout, the inner `marginTop` rendered window, Codex-sized overscan of two turns, measured heights, rendered-window restore, and pending `scrollToKey` reveal. The wrapper owns older-history loading, initial restore offset, latest-turn follow, response spacer, and footer/catch-up coordination. Do not move response-spacer or submit-placement state back into the core list, and do not reintroduce separate top/bottom spacer nodes. Estimated turn heights are scroll math only: mounted turn content must render at natural height, never behind an estimate-sized `height`/`overflow` constraint. First visible turn measurements should commit in a layout-effect pass before paint; later dynamic turn measurements flow through one batched `ResizeObserver` cycle, with pending scroll/restore side effects running after the measured layout state is committed. Programmatic find does not compensate, stick-to-bottom stays at distance `0`, and user mode only adjusts for measured deltas on the viewport bottom side. Row wrappers keep descendant `[data-virtualized-turn-content]` visible; do not add per-row `content-visibility:auto` because transcript chrome can extend outside the row box.
- Protocol-backed long thread history is part of the conversation snapshot contract. The main process resumes app-server threads with a recent `thread/resume.initialTurnsPage` of five full turns, stores `turnPagination` metadata (`olderCursor`, `backwardsCursor`, `oldestLoadedTurnId`, `isLoadingOlder`, `hasLoadedOldest`, `loadedTurnCount`, `itemsView`) on `CodexConversationSnapshot`, and loads older history through `requestLocalConversationOlderTurns(threadId)` / `thread/turns/list` rather than local slicing or a renderer-only cache. Timelines stay oldest-to-newest inside Nodex: descending app-server pages are reversed before merge, existing live/latest turns win on id conflicts, and older pages only prepend missing full turns or upgrade placeholders at the recorded oldest-loaded anchor. After the first resumed page is broadcast, main schedules a background remaining-history load through the same guarded merge path; viewport-top demand loading remains available and shares the same in-flight dedupe. The virtualized wrapper triggers older loads near the loaded-history top with bottom-distance math (`distanceFromBottomPx + viewportHeightPx >= totalHeightPx - 320`) and must preserve the user's measured visible anchor when prepending.
- Thread body remounts restore from renderer session memory keyed by `threadId`, not SQLite. The restore snapshot stores positive `distanceFromBottomPx`, the virtualized rendered-window anchor and measured heights, and latest-turn follow state. `LocalConversationThreadBodyOwner` reads the snapshot once for a thread, passes it to the virtualized list, and writes it back from list restore callbacks and unmount cleanup.
- Latest-turn follow, response spacer, and footer catch-up share the same scroll controller. The footer records submit placement before send/steer/queued-follow-up sends, the virtualized wrapper consumes it when the next latest turn appears, and response spacer state is registered with the controller so the catch-up button hides until the user is beyond `responseSpacerHeightPx + 24`. Latest-turn follow should measure the content area that actually grows, not the whole row; response spacer height is owned outside the core list, animated through the shared Motion spring, and snaps under reduced motion. Composer, rail, search, footer resize preserve, and measured-height compensation must not own separate scroll-mode refs.
- Embedded side-chat stages use the same connected local-conversation stage with `sideChatContext`; omit the normal thread-stage header row because the panel tab strip owns the title, hide the floating summary action, preserve normal composer behavior for the side thread, and block side-chat creation or fork-from-turn actions inside side chats.
- Keep authenticated account quota in the left sidebar footer, not in the thread header or thread summary panel. Signed-out auth remains reachable from the thread header, while the sidebar footer owns the authenticated double-ring quota indicator, account tooltip details, and refresh behavior on pointer hover or when the quota indicator itself has keyboard focus.
- Keep the thread summary panel pinned state local to `WorkbenchShell`: the pinned-open state persists under `nodex:thread-summary-panel:pinned-open`, defaults open for attached local conversation sessions, and mounts as a pinned stage overlay only in shift/gutter modes. Overlay mode renders the separate `Toggle summary` popover branch through the same thread header summary action and must not mutate the saved pinned preference when dismissed. Keep the top-right global header slot responsible for bottom and side panel controls, and let its visible width accept a Motion value so those controls move with animated right-panel geometry.
- Use `@tanstack/react-form` for structured renderer forms with real validation or value coercion; keep simple one-field inputs on local state and use `src/renderer/lib/forms.ts` for shared submit/error helpers.
- Keep runtime validation at boundaries:
  - shared storage / transport / raw JSON schemas live under `src/shared/schemas/*`
  - renderer-only persisted-state parsing lives in `src/renderer/lib/workbench-persisted-schemas.ts`
  - once data is normalized into local reducers/view models, keep the rest of the renderer plain TypeScript instead of re-parsing inside components

## Component SOP
- Start from existing semantics, not from JSX. New UI behavior should usually begin in a projector, bucketizer, normalizer, or other renderer-facing adapter before touching leaf components.
- Keep leaf renderers dumb. Message/tool/request components should consume already-derived props such as lane membership, action eligibility, placeholder state, or copy text instead of recomputing those rules locally.
- Keep one canonical lane per semantic role. Final assistant content, leading user prefix actions, exploration groups, pending-request lanes, and diff lanes should each be derived once and rendered once.
- Keep transcript-special rows dedicated. Items such as context compaction, automatic approval review, and multi-agent activity should render through their own leaf components instead of falling back to generic system banners.
- Keep poor-network reconnect in the transcript, not in shell resume state:
  - retryable transport/turn errors should materialize as `streamError` transcript items with expandable details
  - non-retryable turn failures should materialize as `systemError` transcript items
  - do not reuse `resumeState` placeholders or shell overlays for the `Reconnecting... 2/5` feature
- Prefer rendered behavior over source-looking class strings. If runtime behavior and an apparent source token disagree, treat the rendered CSS/output as authoritative.
- Keep component chrome subdued. Secondary actions should stay small, low-emphasis, and hover-revealed unless the product surface makes them primary. Hover reveal does not imply sequential keyboard focus.

## Frontend Testing
- Run targeted tests while iterating: `bun test src/renderer/...`
- Run isolated UI harness: `bun run dev:storybook`
- Treat Storybook as part of the UI contract. When adding or changing any user-visible UI, update or add the focused stories in the same change instead of leaving Storybook behind.
- Keep Storybook scenes canvas-first: use story variants, `args`, and `argTypes` for presets and controls instead of rendering custom preset/control sidebars inside story pages.
- Keep Storybook scenes production-backed: thread and card-stage stories should build state from the same projection/helpers used by shipped UI instead of hand-authoring parallel fake view models.
- Keep shared UI stories focused. Cover `dropdown`, `popover`, `tooltip`, `button`, `dialog`, and `settings` primitives with explicit regression states such as compact/icon-only triggers, long labels, search rows, flyout submenus, and compact-control tooltips instead of relying on a single catch-all gallery.
- Keep embedded kanban control stories focused on the actual regression surfaces: toggle-list rules/inline controls, card-ref floating toolbars, inline property strips, command-palette filters, and db-view toolbar rules should each have their own visible harness stories.
- Keep `settings/environments` stories flow-complete: workspace root, multi-config project rows, summary, edit, parse error, create-new, and environment-variable popover states should all be separately reproducible.
- Keep selector stories split by feature. Branch and environment selectors should not share one mixed story page; cover default, empty, busy/loading, long-label/path, and icon-sizing states independently.
- Keep menu-driven stories open by default through story-only harnesses. Context menus, sidebar menus, and project manager popovers should render their open state directly instead of asking the reviewer to right-click or click to reveal the actual surface.
- Current thread stories live under `src/renderer/features/local-conversation/view/` for composed stage scenarios and under `src/renderer/features/local-conversation/view/shared/` for focused transcript-special, tool, and request leaf stories. Keep transcript-special surfaces such as reasoning, todo lists, automatic approval review, and multi-agent activity in the transcript-special stories instead of forcing them into tool-call stories.
- Keep tool-call stories scoped to actual Codex tool families. Transcript-special surfaces that happen to originate from tool-like raw items still belong in transcript-special stories once the projector gives them their own semantic lane.
- Default renderer component tests to DOM-based coverage with Bun + `happy-dom` + `@testing-library/react`.
- Assert user-visible structure, labels, and behavior through rendered DOM queries; keep `data-testid` and raw class checks as fallback tools, not the default.
- Reserve HTML-string or server-render assertions for cases where serialized markup is the actual contract.
- Do not add source-string tests that only verify implementation text inside a file.
- Prioritize parser/editor and hook tests for regression safety.
